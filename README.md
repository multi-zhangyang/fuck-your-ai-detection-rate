# FYADR

FYADR 是一个本地运行的文档改写平台，支持 DOCX 和 TXT。

它会保留文档原有的段落边界，把正文按“段落隔离 + 段内分块”的方式交给模型处理，再由用户逐段对照、修改和导出。适合文章、报告、技术文档以及其他需要调整表达方式的长文本。

## 核心功能

- **DOCX 原位回填**：以原文件为格式来源，只替换所选正文段落已有的文字节点，不重新排版整份文档。
- **TXT 简化模式**：直接分段改写并导出纯文本，适合不需要保留 Word 格式的内容。
- **段落隔离与段内分块**：不同段落不会混合；长段落会优先沿完整语义边界继续细分。
- **实时返回**：模型开始输出后即可看到当前进度，不必等待整篇文档完成。
- **多轮改写**：单提示词可执行 1–3 轮；多步骤方案按顺序把上一轮结果交给下一轮。
- **并发处理**：可在 1–16 之间调整，同时保持最终段落顺序不变。
- **停止与继续**：已完成的分块立即保存，继续时只处理尚未完成的部分。
- **循环改写**：完成后可以基于当前审阅结果开启下一轮，并重新选择模型、提示词方案、分块、轮数、并发和保护词。
- **逐段审阅**：同时查看原文、改写后内容和差异，可采用改写、保留原文、手动编辑或重新改写。
- **提醒不干预**：数字、引用、URL 和用户保护词发生变化时只会提醒，不会自动覆盖结果或阻止导出。
- **多模型连接**：内置 DeepSeek 官方连接，也可以添加多个 OpenAI 兼容渠道。

## 正文范围

上传 DOCX 后，可以在开始改写前确认正文范围。标题、目录、题注、关键词、参考文献、表格、公式、页眉页脚等内容默认保留；普通正文可以按文档顺序检查和调整。

![正文范围](docs/images/document-scope.png)

## 模型连接

模型与提示词方案分开管理。一次任务固定使用一个模型，避免处理过程中临时切换渠道造成结果不一致。

支持：

- DeepSeek 官方接口，模型列表动态获取。
- 多个自定义 OpenAI 兼容连接。
- Chat Completions 和 Responses 两种显式协议。
- 可选温度、思考强度、连接等待、首次返回等待、返回中断等待和重试次数。
- 从系统和环境读取网络代理，本地地址自动绕过代理。

请求中不会加入 `max_tokens` 或 `max_output_tokens`。

## 快速开始

环境要求：

- Windows 10 或 Windows 11
- Python 3.10+
- Node.js 18+

不需要 Docker。

```powershell
git clone https://github.com/multi-zhangyang/fuck-your-ai-detection-rate.git
cd fuck-your-ai-detection-rate
.\start_web.bat
```

也可以直接双击 `start_web.bat`。首次启动会自动安装缺少的项目依赖，随后打开 <http://127.0.0.1:1420>。

使用 PowerShell 启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_web.ps1
```

不希望自动打开浏览器时：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_web.ps1 -NoBrowser
```

## 使用流程

1. 在“模型连接”中填写地址和 API Key，获取模型并验证连接。
2. 上传 DOCX 或 TXT。
3. DOCX 先确认正文范围；TXT 直接进入改写设置。
4. 选择模型、提示词方案、分块档位、轮数和并发数。
5. 开始改写；需要时可以停止，之后继续未完成内容。
6. 在逐段对照中确认结果，必要时手动修改。
7. 直接导出 DOCX/TXT，或重新选择本轮设置后继续改写。

默认使用“标准”段内分块和两轮改写。还可以选择更细的分块或适合长段落的分块方式。

## DOCX 格式保留方式

FYADR 不根据外部模板规则重新设置字体、字号、行距、缩进和页边距。导出时会复制原 DOCX，并在 `word/document.xml` 中定点替换已选正文的文字：

- 保留原段落、文本节点、样式、编号、超链接关系和分节信息。
- 保留页眉页脚、主题、图片、表格、公式及其他包部件。
- 未选择的正文区域保持不变。
- 正文中的行内对象固定在原位置，对象前后的普通文字仍可处理。
- 导出后检查包部件、文档结构、未选区域和文件可读性。

文字长度改变后，Word 仍可能重新换行或分页，因此项目不会宣称任意 DOCX 都能达到 100% 视觉一致。发现格式风险时，应用会说明风险，但是否继续导出由用户决定。只有源文件损坏、目标文字不存在、内容无法写入或文件无法生成时，才会报告无法生成 Word，并保留 TXT 导出。

当前不改写表格单元格、公式对象、页眉页脚和纯图片中的文字。

## 分块与多轮

DOCX 和 TXT 都先按段落处理。长段落会继续在句号、问号、分号等语义边界拆分，超长单句才会退到逗号、空白或长度边界。任务创建后，分块顺序和连接符保持固定，多轮改写和断点继续都复用同一份分块清单。

完整非空的模型输出会先保存，再生成提醒。提醒算法出现异常也不会改变已经完成的结果；流式输出中断或返回空内容时，只暂停当前分块，不会用原文冒充改写结果。

## 提示词方案

项目提供一个侧重调整表达、降低文本 AI 检测特征的经典改写模板。内置模板只读，可以复制后修改；用户也可以按其他改写目标创建自定义模板和包含 1–3 个有序步骤的方案。

自定义提示词保存在本机配置中。一次任务会保存当时使用的提示词快照，之后修改模板不会改变已经开始的任务。

完成后的“继续改写”会创建新的任务快照，默认继承上一轮设置。用户修改模型或提示词方案后，新一轮会使用新的连接与提示词，并以当前采用、保留或手动编辑后的正文作为输入。

## 本地数据与安全

- 后端默认只监听 `127.0.0.1`。
- API Key 保存在本机用户配置目录，不写入仓库。
- 浏览器接口只返回密钥占位符和尾号预览。
- 文档、任务进度和导出文件保存在本机数据目录。
- 最近文档最多保留 20 条，删除前需要确认。

配置位置：

- Windows：`%APPDATA%\FYADR\config.json`
- macOS / Linux：`~/.fyadr/config.json`

旧配置首次迁移到 schema v6 前，会在同目录保留 `config.before-v6.json`。

## 开发与验证

```powershell

python scripts/web_app.py

# 终端 2

```

```powershell
python scripts/run_regressions.py
```

```powershell
python scripts/run_regressions.py --include-browser-e2e
```

回归覆盖实时返回解析、超时、停止、继续、代理、重试边界、1–16 并发顺序、段内分块、多轮衔接、提醒不回退、逐段审阅、DOCX 原位回填和响应式界面。
